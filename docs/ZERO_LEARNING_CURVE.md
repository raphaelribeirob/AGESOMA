# AGESOMA Zero Learning Curve

AGESOMA must be usable by someone who knows nothing about AI, agents, prompts, workflows, APIs, models or automation.

## Product test

If a person can delegate something to a capable assistant, they must be able to delegate it to AGESOMA.

No prompt engineering. No agent configuration. No workflow builder. No model selection.

## Canonical interaction

The primary experience is one conversation:

1. **Ask or delegate** — describe the desired outcome in normal language.
2. **Follow** — see only meaningful progress, blockers and completed work.
3. **Decide** — intervene when judgment or authorization is required.
4. **Verify** — receive the result and relevant evidence in the same conversation.

## Language

Never require the user to understand:

- agent;
- prompt;
- model;
- token;
- workflow;
- orchestration;
- tool calling;
- autonomy levels;
- Sentinel;
- HERMES;
- Work Cell;
- vector memory.

Prefer:

- "O que você quer que eu resolva?"
- "Vou cuidar disso."
- "Estou trabalhando nisso."
- "Preciso da sua autorização para uma coisa."
- "Concluído."
- "Isto foi o que encontrei."
- "Isto foi o que mudou."

## First-use experience

Within seconds, the first screen should answer:

1. What can I delegate?
2. Is AGESOMA already doing anything for me?
3. Does anything need my attention?

When context is limited, the dominant invitation is:

**O que você quer que eu resolva?**

## Onboarding

Target: under one minute before first delegation.

Ask only for:

1. minimal personal context;
2. where the user most wants to recover time;
3. the first real task.

Connections and permissions should be requested just in time, when they unlock the requested outcome.

## Permissions

Describe the real-world effect, not the internal capability.

Bad:
"Grant write access to calendar."

Good:
"Posso criar este compromisso no seu calendário?"

Bad:
"Approve messaging action."

Good:
"Posso enviar esta resposta para Ana?"

## Progressive disclosure

Hide by default:

- execution logs;
- model/runtime settings;
- policy internals;
- memory internals;
- connector scopes;
- technical costs;
- automation configuration.

Expose detail only when the user asks or when a decision requires it.

## Personalization

Learn progressively from behavior and corrections:

- concise vs detailed updates;
- when to interrupt;
- preferred meeting buffers;
- communication style;
- recurring priorities.

Personalization may change presentation and prioritization. It never expands authorization.

## Success criteria

- A first-time user knows what to do within 5 seconds.
- The first useful request needs no AI terminology.
- The core experience does not require dashboard navigation.
- No primary screen contains internal architecture terms.
- Consequential actions request concrete approval.
- The user can return later and understand what happened.
- Learned context can be corrected or forgotten in ordinary language.

## Canonical principle

> AGESOMA should feel less like operating AI software and more like delegating to a capable personal executive assistant.
